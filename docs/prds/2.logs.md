# Feature: Estructura General de Logs

## Objetivo

Definir la estructura base que un log debe seguir en la aplicación, sin importar si es para comandos o lo que sea (inicialmente se piensa solo el caso de comandos)

## Alcance

### Incluye

- Estructura definida de log
- Usuario que involucra la acción (puede ser `bot`)
- Timestamp del log
- Registro en un archivo .log
- Niveles de log (debug, info, error, warning y critical)

### No incluye

- Casos específicos para un tipo de log exacto 
- Timezones personalizados(usa UTC únicamente)
- Persistencia en base de datos

## Comportamiento

- Se usa función de log en el código
- Se piden valores base como `author`, `action`, `target_channel`, `level`, `mensaje`.
  - Si target_channel es None usar `system`
  - Author None entonces `app`
  - - Si se usa level incorrecto usar `INFO`
- Se loguea en consola y en el archivo

## Casos borde

- El log es demasiado extenso, por ahora se guarda igual
- No se especifica author, por defecto es `app`
- El archivo alcanza un límite máximo de peso (TBD), pero se debe poder especificar en un `config.json`
- No se puede escribir el archivo
- Mensaje contiene carecteres especiales, debe funcionar igual

## Criterios de Aceptación

- Se debe seguir el formato `{timestamp} - {level} - {author} - {target_channel}: [{action}] {mensaje}`
- Debe quedar registrado en `registro.log`. A futuro debe especificarse por cada canal (referenciado en [tech debt](../tech_deb/logs.md))
- Se debe mostrar el log consola con el formato `{timestamp} - {level} - {author} - {target_channel}: {mensaje}`
- El archivo debe quedar guardado en carpeta `logs/`
- Según el nivel debe mostrarse en el color que corresponda:
  - WARNING: Amarillo
  - INFO: Verde
  - DEBUG: Azun
  - ERROR: Rojo
