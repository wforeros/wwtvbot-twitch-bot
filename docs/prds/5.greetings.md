
# Feature: Notificación de primer mensaje durante un stream

## Objetivo

Los usuarios nuevos cuando llegan a un directo y escriben por primera vez no deberían ser ignorados

## Alcance

### Incluye

- Revisión de mensajes de usuario para identificar si es el primer mensaje o no
- Actualizar el estado del usuario una vez envíe un mensaje por primera vez (is_first_message: bool)
- Al finalizar el directo se debería reiniciar, para que en el próximo vuelva a identificar los primeros mensajes
- Almacenar información en una nueva tabla que se llame `first_appearance`
- HTML básico para mostrar los nuevos mensajes
- No debería ser necesario recargar la página para ver las notificiones nevas

### No incluye

- Plugin de OBS
- Limpieza de lista en el HTML. Es decir que siempre se van a ver todos los usuarios que entren
- No habrá posibilidad de marcar si ya saludé a alguien

## Comportamiento

- Usuario entra al stream
- Envía su primer mensaje al chat
- El bot debe detectar que es su primer mensaje
- El bot guarda el registro en base de datos
- Se debe mostrar la notificación en el html

## Casos borde

- Usuario saluda después de mucho tiempo inactivo => No debería pasar nada, se mantiene el registro original
- Usuario es baneado => No debería pasar nada, se mantiene el registro original
- El mensaje es eliminado => No debería pasar nada, se mantiene el registro original

## Criterios de Aceptación

Como streamer debería poder ver el primer mensaje de cualquier usuario durante mi stream
Como streamer solo con prender directo debo poder ver que no hay mensajes pendientes por revisar
Como streamer no debo tener que recargar la página para poder ver los nuevos mensajes que han llegado
Como streamer debo poder ver el contenido del mensaje, la hora a la que fue enviado y el usuario que lo envió

## Notas técnicas

- Inicialmente se va a usar SQLite para la base de datos, ya que el flujo de mensajes no debería ser muy grande
- El HTML no va a tener diseno, solo muestra la lista de mensajes con la información descrita en los criterios de acepttación 
- Para no tener que recargar la página, se va a considerar el uso de websockets. Se mantendrá la alternativa de Long Polling

## Tech Debt

Inicialmente se va a mostrar en un html/terminal, pero idealmente debería estar en OBS integrado
